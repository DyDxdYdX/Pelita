# MVP scope

The documentation baseline precedes application work. **Phase 1 is the core projection MVP.** Its first pilot is a prepared Sabbath service on a configuration that passed Phase 0. The playlist can use manual text slides and imported local files before the searchable catalog arrives.

| Required for Phase 1 | Deferred or conditional |
| --- | --- |
| Operator preview and live output, keyboard navigation, Black, Clear, projector recovery | Additional display layouts, richer themes, global shortcuts |
| Static PDF and image decks, manual text slides, MP3 accompaniment, validated MP4 playback | Direct PPTX conversion only after a successful spike. Animated slides, transitions and embedded media playback deferred. |
| Local playlist editing, ordering, reuse, and preflight | Searchable song library and variant presets in Phase 2 |
| Offline rehearsal and pilot packaging for validated targets | Local content packs in Phase 3, registry in Phase 4, public release in Phase 5 |

Use PDF export before worship as the PPTX fallback. Treat validated codecs and display configurations as a release contract. Keep one live item, one audible transport, one projector output, and one local operator per installation. Use original or cleared fixtures for development and pilots. LPMI distribution follows its own [permissions gate](../legal/content-permissions.md).

Streaming, cloud sync, accounts, subscriptions, executable plugins and multi-operator networking sit outside this plan. See [requirements](requirements.md) and [milestones](../development/milestones.md).
