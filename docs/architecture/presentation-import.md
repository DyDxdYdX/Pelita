# Presentation import

An imported PPTX becomes one slide item in the current service. Pelita keeps its original and its prepared images locally. Native text and image items, PDF imports, service files, playback, and projector controls keep their existing entry points.

## Conversion

The operator picks PPTX files in a native dialog next to the existing media import, or drops them onto the operator workspace. Only the backend sees the file paths, allowing it to read each file with bounded copying and carry Windows zone information into staging. Rust validates the staged OOXML package before any provider opens it. A single job per profile runs on a blocking worker and publishes ordered slides and thumbnails only after the complete result validates. It reports actual slide counts where available and describes stages otherwise. Batch imports are sequential and skip individual failures. Cancelling a batch keeps items already saved.

The manager tries operational Windows PowerPoint first in Automatic mode, then LibreOffice. macOS and Linux use LibreOffice. Source, cancellation, and storage errors end the attempt. A provider failure permits one fallback in Automatic mode. Explicit selection returns the selected provider's error and identifies any available alternative. Preferences use the application profile and are independent of a service.

PowerPoint uses a serialized COM single-threaded apartment, opens only a staged read-only copy, and exports slides by index using Slide.Export. Pelita restores the application's automation security immediately after opening and never quits PowerPoint. A blocked COM call can outlive an import timeout or cancellation. Pelita abandons its result and lets the worker close only its staged presentation when the call returns. The next PowerPoint attempt must wait for the worker. Security prompts remain in Office's control.

LibreOffice runs headless with a temporary profile, macro security set to Very High, and PDF export with hidden slides included. Native Hayro renders the local PDF page by page at bounded dimensions. Hayro and image use MIT or Apache-2.0. They build with Cargo on all supported targets and need no PDF runtime or bundled platform binaries. PDFium has a mature rendering engine but adds native binaries, notices, and platform packaging. Existing PDF.js is also mature and already bundled for standalone PDF imports, but reusing it for PPTX would require moving the intermediate PDF and prepared images across the desktop IPC boundary. Hayro renders on the CPU and has known limitations with some transparency and blend effects. LibreOffice, PowerPoint, and substituted fonts can all change fidelity.

## Storage and projection

Each complete generation has a UUID directory under the app data directory's presentations folder, with the original PPTX, metadata, ordered PNG slides and separate lazy-loaded WebP thumbnails. Metadata records the source SHA-256, actual provider/version, import time, original and rendered dimensions, warnings, settings, and cache version. Duplicate imports verify original, slide, and thumbnail digests before reuse. Preflight verifies the full-size slide digests without holding the service lock. Regeneration creates a new generation and updates only the selected item after successful conversion. Old generations remain available to other service entries and live snapshots. Removing an item removes its service reference. The application retains managed data for reuse and never writes back to the selected source file.

Projector and preview continue to use their normal image-slide representation and aspect-preserving fit. The projector only receives access to currently authorized slide images. PPTX originals, metadata, and conversion scratch paths are private to the backend. A first-class source descriptor on a slide item records its provenance and can be extended when adding a source format.

## Verification

Tests must cover bounded validation, provider policy and errors, reusable storage, cancellation, regeneration and persistence. Rehearse the packaged workflow with a real provider on each target, including live image jumps during MP3 playback, operator layouts from 800×600 to 1920×1080, Windows Office security prompts and existing unsaved presentations. Record platform and provider versions with observed results.

PowerPoint's macOS scripting dictionary exposes presentation objects and PowerPoint save formats, including PDF. An AppleScript/Apple Events adapter would require testing noninteractive export, sharing and document ownership on supported Office versions, macOS Automation consent, NSAppleEventsUsageDescription, and a signed hardened-runtime Apple Events entitlement. This milestone registers no macOS PowerPoint provider. ## Trust boundaries and resource limits

The operator window invokes native file selection and receives opaque IDs. The projector cannot invoke import or settings commands. The existing media protocol only serves managed slide/thumbnail image paths, and only the live full-size slide is authorized for the projector. The content security policy is unchanged.

Validation checks OOXML and ZIP headers before automation. It limits the input to 128 MiB, expanded package data to 512 MiB, and presentations to 100 slides. It refuses encrypted or malformed ZIPs, unsafe paths, ZIP64 and multi-volume archives, unsupported archive methods, XML DTDs, macros, active objects, and external-content relationships. Package XML must use UTF-8. Ordinary web and mail hyperlinks can stay in the source as inert links. Embedded XLSX chart data shares the package expansion limit and is subject to checks for external connections and active content. Import uses a managed snapshot and never overwrites the source.

On Windows Pelita carries the source's Zone.Identifier stream into staging and marks network-drive files whose source has no stream. PowerPoint runs with existing Trust Center and Protected View behavior. A failed or timed-out open or export of a security-marked deck returns a source error. Pelita only closes the presentation object it opened using its own private path. The Windows worker uses the COM STA and releases all COM interfaces before uninitializing it. An Office modal dialog can hold the worker, delay restoring the process-wide automation setting, and leave the staged copy open until Office responds. The setting is process-local. If restoration fails, save open work and restart PowerPoint and Pelita. [Office automation security](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.application.automationsecurity) · [Read-only and windowless open](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentations.open) · [Slide export API](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.slide.export)

LibreOffice runs in a private subprocess group on Unix and a memory-limited Windows Job Object. It uses a separate profile with macros and active content disabled and untrusted links blocked. Visible output is bounded to Full HD, a 64 MiB intermediate PDF, and 384 MiB of full slide images per conversion. The external export attempt has a 120-second deadline. PPTX and PDF normalization check cancellation and deadlines at bounded stages, including between rasterized pages. A page render can delay cancellation until its current unit completes. Pelita retries staging cleanup on startup after an unexpected exit.

Converters run under the desktop user's permissions. Archive validation and profile isolation reduce exposure but cannot create an operating system network or file sandbox for an installed office application, its add-ins, or its update checks. A custom LibreOffice executable is software chosen locally by the operator and runs with those permissions. Keep the installed converter patched.

## Adding a provider or source

Implement `Converter` in the Rust presentation module and register it in platform preference order. Return the actual installation version, capability flags, and an ordered conversion with slide dimensions and warnings. Use structured provider errors for recoverable failures and source or storage errors for failures that apply to every provider. Reuse the storage and projection paths. Add a source descriptor and validator for a new input format if its trust boundary differs from PPTX.

The direct Rust dependencies for the import are ZIP, quick-xml, and rfd (MIT), plus Hayro, image, sha2, tempfile, URL, libc, and windows-rs (MIT or Apache-2.0). Dunce is CC0-1.0, MIT-0, or Apache-2.0. Several of these were already transitive dependencies. rfd uses the existing GTK 3 dependency on Linux. Office and LibreOffice are optional local installations. Pelita redistributes neither application. See Cargo.lock for the full graph.
