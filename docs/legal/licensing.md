# Application licensing

Pelita is intended to be free and open-source. The code license is pending. Record the choice before publishing implementation code as open source, soliciting contributions or distributing builds.

| Candidate | Commercial reuse and derivative works | Maintenance implications |
| --- | --- | --- |
| MIT | Permits commercial use and proprietary redistribution or modification subject to preserving its notice and permission terms. | Short notice requirements. No express patent grant in the license text. |
| Apache-2.0 | Permits commercial use and proprietary derivatives. Includes an express contributor patent grant with termination terms. | Preserve license and applicable notices, mark modified files and handle NOTICE obligations where applicable. |
| GPL-3.0 | Allows commercial use. Conveying covered binaries or derivatives generally requires GPL licensing of the covered work and provision of corresponding source under the license terms. | Review combined-work and dependency compatibility, distribution procedures, and any applicable installation information duties. Decide whether to choose GPL-3.0-only or GPL-3.0-or-later if selected. |

Choose MIT if minimal permissive terms matter most, Apache-2.0 if an express patent grant matters, or GPL-3.0 if reciprocal source availability for conveyed derivatives is a priority. Review licenses against actual dependency versions, linking and packaging, including playback engines, codecs, converters, fonts and installer payloads. Maintain a dependency and notice inventory. [MIT text](https://opensource.org/license/mit) · [Apache-2.0 text](https://www.apache.org/licenses/LICENSE-2.0) · [GPL-3.0 text](https://www.gnu.org/licenses/gpl-3.0.html)

Contributors ordinarily retain copyright in their contributions unless a separate arrangement changes ownership. Document inbound contribution terms and decide whether a Developer Certificate of Origin is appropriate before opening contributions. A code license covers the rights granted in code. Track content and assets separately and attach the required notices and permissions to each distributable pack. See [content permissions](content-permissions.md).
