# Development milestones

Each phase closes with recorded acceptance evidence, known limitations and a maintainer decision. Limit each spike to a small question and one fallback comparison. LPMI permissions run independently of engineering delivery.

| Phase and objective | Deliverables and dependencies | Acceptance and testing | Risks and definition of done |
| --- | --- | --- | --- |
| 0 · Establish feasibility | Throwaway spike builds, cleared fixtures, compatibility matrix, and ADR evidence. Needs real dual-display access on Windows, macOS and Linux, plus a reference low-resource machine. | Show private preview and confirmed projector Take, advance slides during MP3 playback, play candidate MP4 and import PDF/PPTX samples offline. Test mirror, unplug, reconnect, restart, mixed DPI and available X11/Wayland sessions. | Window placement, codecs and conversion fidelity. Done when each candidate capability has evidence, an accepted fallback, a reduced support claim or a recorded blocker. |
| 1 · Core projection MVP | Prepared slide assets, transport, display lifecycle, local playlists, preflight and pilot packages. See the [Phase 1 record](phase-1.md) for implementation and outstanding pilot evidence. Needs Phase 0 support floor. | Pass PRJ-01–04, MED-01–03, IMP-01 and SVC-01–02 in a two-hour offline rehearsal. Test persistence, missing media, keyboard use and recovery. | Live regressions and decoder failures. Done after a volunteer pilot and closure of defects that could expose private preview, lose committed data or stop a service without recovery. |
| 2 · Song library | Collections, search, manual songs, variants, preferences and relinking. Needs Phase 1 asset and playlist model. | Pass LIB-01–03 and NFR-04 with invented Unicode fixtures, duplicate song numbers across books, missing assets and migrated Phase 1 data. | Search ranking and stale links. Done when older playlists reopen and a volunteer can find and take each supported variant offline. |
| 3 · Extension foundation | Versioned manifest and schema, local songbook install, enable, disable and uninstall. Needs Phase 2 catalog model and staging. | Pass EXT-01, NFR-11 and generic LPM-01 schema tests. Interrupt install and verify reference and index behavior. | Unsafe archives and orphaned references. Done when synthetic packs work offline and invalid packs leave active state intact. |
| 4 · Extension marketplace | Static registry, discovery, compatible downloads, explicit updates and rollback. Needs Phase 3 lifecycle and registry trust policy. | Pass EXT-02 with compatible and incompatible updates, digest mismatch, stale registry and interrupted downloads. | Registry trust and publisher identity. Done when publication rules and recovery procedures are documented and installed packs work during outages. |
| 5 · Community release | Public guides, contribution process, selected license, dependency notices, packaged builds, support matrix and GitHub Releases. Needs release credentials and completed gates for features advertised. | Clean install and offline rehearsal on every advertised target. Verify artifact provenance, signing where applicable, upgrade and backup/restore. | Signing, runtime prerequisites and maintenance capacity. Done when release artifacts and limitations are published with reproducible build instructions and a support path. |

## First milestone

Run a thin vertical slice on one available dual-display machine, then repeat on the other target systems before closing Phase 0. Use an invented three-slide deck, a continuous MP3 and one candidate MP4. Verify privacy, navigation with uninterrupted audio, Black and Clear, unplug/reconnect, and playback switching. Follow with separate PDF and PPTX fidelity probes. Record the platform evidence and resolve [ADR 0001](../decisions/0001-desktop-framework.md) before using spike code as the basis of the application.
